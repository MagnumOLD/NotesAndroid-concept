# NotesAndroid Concept — правила проекта

## Границы проекта
- Этот репозиторий — самостоятельное приложение новой версии NotesAndroid.
- Эталон актуального дизайна и существующих взаимодействий: `MagnumOLD/NotesAndroid-Build`, ветка `main`.
- `NotesAndroid-Build` и старый `NotesAndroid` используются только для чтения. Никаких коммитов, веток, PR, workflow-запусков или изменений в этих репозиториях.
- Вся новая разработка, сборка и тестирование выполняются в `MagnumOLD/NotesAndroid-concept`.
- Уникальный applicationId: `com.magnumold.notes.concept`. Не переиспользовать applicationId старого приложения.

## Дизайн
- Сохранять визуальный язык эталонного NotesAndroid: направляющие, горизонтальные отступы, типографику, карточки, подборки, drag handle, кнопки, темы и правила выделения.
- Базовая направляющая контента — 20 dp от краёв экрана; основной текст карточек — 16 sp; заголовок главной — 18 sp; минимальная высота карточки — 88 dp, если конкретный компонент не требует иного.
- Общие параметры оформления должны иметь единый источник истины. Не вводить случайные отступы и размеры на отдельных экранах.
- Светлая, тёмная и пользовательская темы. По умолчанию использовать тему устройства; ручной выбор доступен в настройках.
- Не менять утверждённый внешний вид существующих элементов без явной необходимости и проверки.

## Продуктовая модель
- Главная страница — общая хронологическая лента карточек всех активных модулей.
- Первый набор модулей: Заметки, Задачи, Таймеры, КБЖУ, Тренировки, Покупки.
- Модули включаются и отключаются пользователем. Отключение модуля не удаляет его данные.
- Карточка на главной открывает соответствующий объект. Интерактивный режим карточек включается отдельно и настраивается.
- Карточки поддерживают дату создания и отдельную плановую дату отображения, ручное скрытие с главной, архив, избранное, корзину и перемещение.
- Создание заметки: быстрое открытие редактора с клавиатурой и автосохранение при выходе.
- Подборки настраиваются отдельно внутри каждого модуля.
- Подробная утверждённая спецификация: `docs/PRODUCT_PLAN.md`.

## Архитектура и данные
- Сначала сохранять работающую основу и пользовательские данные, затем постепенно вводить модульные границы.
- UI не должен обращаться напрямую к хранилищам или содержать бизнес-логику.
- Модели, операции, репозитории, навигация, состояние и UI должны иметь явные границы.
- Формат существующих данных и резервных копий сохранять до появления проверенной миграции.
- Сложные жесты и reorder переносить без регрессий; не переписывать их одновременно с несвязанными функциями.
- Не добавлять новые модули в ущерб корректному сохранению и восстановлению данных.

## Разработка и проверка
- Работать только в ветках этого репозитория.
- Перед изменениями изучать текущий код и зависимости.
- Делать небольшие логически законченные коммиты.
- Собирать debug APK и запускать unit-тесты раздельно; UI/instrumentation tests запускать на ключевых этапах и перед финальной выдачей.
- Не объявлять сборку успешной без подтверждённого успешного workflow и наличия APK-артефакта.
- Не выдавать старый APK за сборку нового коммита.
- Отчёт о каждом этапе: изменённые части, коммит/ветка, реально выполненные проверки, статус APK.
- Не считать работу выполненной только потому, что добавлена документация или создана заглушка UI.
